# Checklista review proposal

## Problem and outcome

- [ ] Proposal opisuje problem i oczekiwany rezultat, nie tylko rozwiązanie techniczne.
- [ ] Wartość dla użytkownika lub projektu jest czytelna.
- [ ] Proposal nie łączy kilku niezależnych zmian.

## Sources

- [ ] Każda istotna reguła ma source lub decision ID.
- [ ] Working assumptions są jawnie oznaczone.
- [ ] Konflikty nie zostały rozstrzygnięte przez autora/Claude bez decyzji.

## Scope

- [ ] In scope jest wystarczająco mały i konkretny.
- [ ] Out of scope wyklucza kuszące rozszerzenia.
- [ ] Nie ma niezatwierdzonej zależności, migracji ani kontraktu.

## Open questions

- [ ] Pytania mają ownerów.
- [ ] Pytania blokujące są rozwiązane albo proposal ma status rework.
- [ ] Proposal nie ukrywa decyzji w języku „implementation detail”.

## Decision

- [ ] Approved
- [ ] Approved with conditions
- [ ] Rework required
